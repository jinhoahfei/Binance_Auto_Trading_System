## 오류 기록의 완전성

- UI 진단 4,546건, backend 진단 3,832건의 sequence가 각각 1부터 끝까지 연속이다. JSON 해석 실패·중복·기록된 유실은 모두 0건이다.
- 저장 실패를 주입한 첫 장애에서 고정 저장 실패 메시지 2회가 발생했다. 이후 최초 오류를 포함한 모든 기록이 보존됐고, 최초 오류 95개 모두 서로 다른 incident와 복구 완료 기록으로 연결된다.
- backend 오류 95회는 모두 같은 시점에 강제로 닫은 연결과 대응한다. 94회는 EOF(`_WebSocketClosed`), 1회는 TCP reset(`ConnectionResetError`)으로 관측됐다. reset 1회도 64번째 주입 장애의 같은 연결에서 약 60ms 뒤 기록됐으며 정상 복구됐다. 이는 추가로 발생한 장애가 아니다.
- backend의 `operation_failed` 95건은 위 연결 종료의 예외 상세 기록이므로 별도 장애 95건으로 중복 집계하지 않는다.
- UI 마지막 event cursor는 42,082다. 수신 41,935건과 전체 snapshot으로 대체한 cursor 이동 147건의 합과 정확히 일치한다. 연결 단절 중의 상태는 전체 snapshot으로 다시 읽으므로 해당 147건을 진단 로그 유실로 해석하지 않는다.
- 최종 측정치의 backend 발행 수 42,079는 마지막 5초 주기 표본이다. 종료 직전 backend 소켓 로그와 UI의 최종 cursor는 모두 42,082이며, 측정 시점 차이를 누락으로 집계하지 않는다.

초기 자동 대조는 모든 강제 종료가 EOF일 것으로 좁게 가정해 reset 1건을 검토 대상으로 표시했다. 연결 ID·시각·sequence를 추가 대조해 같은 강제 종료에 따른 reset임을 확인한 후 최종 결과를 확정했다. 초기 분석 결과도 보존했다.

## 수신 지연과 자원 사용

5초 주기 측정 17,266건을 분석했다. 최대 측정 간격은 5.234초였고, 관측된 최대 마지막 수신 이후 시간은 60.169초였다. 값 변화가 없는 대기 구간에서도 75초 무응답 판정에 따른 불필요한 복구는 없었다. 시간대별 발행 계수 정체 구간에서도 생존 신호가 이어졌고 모든 시간대에 의도한 긴 대기가 관찰됐다.

진단 `heartbeat`는 매 이벤트를 저장하지 않고 주기적으로 요약하므로, heartbeat 로그 행 사이의 간격을 실제 이벤트 무수신 시간으로 해석하지 않는다. 무수신 평가는 5초 측정의 `since_last_event_seconds`와 실제 오류 기록을 사용했다.

## 종료와 적용 범위

Node(62795), Python(62819), 점검 동안 자동 잠자기를 막던 프로세스(62796)는 분석 시점의 OS 조회에서 모두 종료된 것을 확인했다. 최종 metrics의 `TCPServerWrap`·`ProcessWrap` 표시는 Vite 종료 직전의 표본이며 남아 있는 프로세스의 증거가 아니다. 검증 중 생성한 WebSocket 연결 96개의 backend 종료 기록도 모두 존재한다.

이 점검은 운영 Python HTTP/WebSocket·DTO·heartbeat worker와 UI adapter를 사용하지만, 계좌 상태는 모의 runtime이고 UI callback은 실제 화면을 그리지 않는다. UI 로그의 최종 저장은 Node 파일 sink를 사용한다. 따라서 실제 WebView 표시, Tauri IPC 저장 전체 경로, 매매 전략, 실제 Binance 계좌·주문, 프로그램 종료 버튼의 전체 절차는 24시간 검증 범위 밖이다. 그중 native 저장·화면 상태·안전 종료는 앞선 별도 회귀 테스트 결과를 참고한다.

분석 시 비교한 실행 코드 9개 파일의 SHA-256은 시작 기록과 모두 일치한다. 이 검증을 위해 프로그램 동작 코드를 추가 수정하거나 점검을 다시 시작하지 않았다.
