# 화면 갱신 과부하와 자동 복구 수정

검증일: 2026-09-15 (KST)

## 장애와 재현

실제 20:28:54 연결 로그는 `stage=publish`, `error_type=Unknown`, `BACKEND_EVENT_STREAM_FAILED`를 기록한 뒤 UI 연결을 닫았다. 백엔드는 계속 실행 중이었고 사용자가 20:29:11에 연결 다시 확인을 누른 뒤 같은 세션으로 복구됐다.

Chromium의 실제 App·React 외부 store·facade·backend adapter를 연결한 주문 비활성 fixture에서 정상 형식의 거래 상태 이벤트 300개를 연속 전달했다. 수정 전에는 54번째 이벤트에서 React의 `Maximum update depth exceeded`가 발생했다. 이 예외가 실제 장애와 동일한 publish 단계의 Unknown 및 포괄적인 연결 실패 코드로 바뀌는 경로를 재현했다. 당시 실계좌 로그에는 예외 원문이 없으므로 이 비교가 당시 예외 원문까지 증명하는 것은 아니다.

화면 복귀 시 미뤄진 이벤트가 한꺼번에 처리되면 매 이벤트의 동기 React 알림이 중첩 갱신 제한에 걸릴 수 있었다. 기존 코드에는 오류 이후 최신 상태를 자동 재조회하는 경로도 없었다.

## 변경

1. **화면 알림을 프레임마다 한 번으로 합침.** 각 이벤트의 facade 상태와 캐시 ViewModel은 즉시 갱신한다. React 구독자에게 알리는 작업만 같은 화면 프레임 안에서 합쳐 마지막 상태를 표시한다. 사용자 클릭과 native 종료 요청은 즉시 반영하며 종료 시 미뤄진 알림을 취소한다.
2. **오래된 수신 대기열 차단.** 절전이나 WebView 정지로 timer와 visibility 이벤트도 늦어진 경우, 첫 수신 frame을 화면에 반영하기 전에 시간 공백을 확인한다. 오래된 연결의 대기 이벤트를 적용하지 않고 검증된 전체 snapshot부터 다시 받는다.
3. **제한된 자동 복구.** 동기 event 반영과 비동기 화면 알림의 오류를 같은 복구 경로로 보낸다. 같은 인증과 주문 식별자를 보존해 최신 snapshot을 다시 받고 정상 event 수신을 확인한 뒤 연결을 복원한다. 실패한 이벤트나 사용자 명령을 재실행하지 않는다.
4. **반복 실패 제한.** 화면 반영 오류의 자동 복구는 세 번까지 허용한다. 한 이벤트의 성공만으로 횟수를 초기화하지 않고 60초의 정상 수신·반영 후 초기화한다. 형식·인증·세션 검증 실패는 기존 차단을 유지한다. 복구 안내 자체의 예외도 예정된 snapshot 복구를 취소하지 않는다.
5. **원인별 안내와 진단.** 화면 반영 실패, 통신 중단, 응답 지연, 데이터 형식 불일치를 한국어로 구분하고 원래 코드는 접힌 오류 세부 정보에 둔다. 일반 Error도 Unknown과 구분하며 허용된 UI store/facade 소스 위치를 기록한다. 예외 원문·전체 stack·URL·인증 값은 저장하지 않는다.
