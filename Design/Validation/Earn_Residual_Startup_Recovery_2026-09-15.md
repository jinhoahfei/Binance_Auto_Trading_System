# Earn 잔여 ETH와 시작 실패 안내 수정

검증일: 2026-09-15 (KST)

## 확인된 원인

저장된 잔여 원금은 ETH 0.00009600이었지만 해당 ETH가 Binance Simple Earn으로 자동 예치되어 현물 잔고는 0이었다. 기존 시작 검증은 현물 지갑만 비교해 `ORDER_RECONCILIATION_FAILED`로 종료했다.

조사 중 사용자가 직접 상환했다. 상환 후 현물 지갑에는 원금 0.00009600과 확인된 REALTIME 보상 0.00000001을 합친 ETH 0.00009601이 들어왔으며, Earn 보유량은 0이었다. 기존 비교식은 이 보상 차이도 설명하지 못했다.

macOS 안내는 시작 연결 실패 직후 아직 자식 프로세스 종료를 관찰하지 못한 상태를 “백엔드는 실행 중”으로 표시했다. 백엔드 정리가 끝난 뒤에도 표시된 대화상자가 남아, 활성 상태 보기와 안내 내용이 달라졌다.

## 수정 동작

- 현물 수량이 장부와 다를 때만 고정된 Binance 조회 경로로 ETH Earn 보유량·자동 예치·상환·보상을 확인한다.
- 성공한 AUTO/SPOT 예치, 완료된 PAID/SPOT 상환, 공식 REALTIME 보상 기록과 수량 합계가 일치해야 한다. 예치 시점에 이미 발생한 잔여 또는 앞서 상환한 금액으로 설명되는 자동 재예치만 인정한다.
- 현물 계좌와 Earn 근거를 반복 조회하여 도중에 바뀐 상태로 시작을 허용하지 않는다. 전략 포지션의 부족분은 Earn 잔여로 대신 채우지 않는다.
- 잔여 원금·원가·거래 기록은 보존한다. Earn 자산과 보상을 전략 포지션으로 편입하지 않는다.
- 근거가 불완전하거나 다른 자산 이동으로 수량이 설명되지 않으면 시작을 계속 차단하고 `RESIDUAL_BALANCE_MISMATCH`를 기록한다.
- READY 전 실패는 허용된 고정 코드만 native 부모에게 전달한다. 토큰·예외 원문·계좌 비밀값은 이 메시지에 포함하지 않는다.
- native 안내는 실제 종료 관찰을 최대 2초 기다린 후 실패 원인과 확인된 종료 상태를 표시한다. 대기 시간은 프로세스를 강제 종료하는 조건이 아니다.

조회 범위는 최초 잔여 발생 시점 이후, 최대 120개의 30일 구간이다. 각 구간의 페이지 수와 전체 건수를 검증하며 잘린 이력을 완전한 근거로 사용하지 않는다. 수동 예치, 혼합 자금 출처, 담보 사용 또는 지원하지 않는 보상 유형은 자동 복구 대상으로 인정하지 않는다.

API 필드·시간 범위 참고: [Binance Simple Earn 공식 문서](https://developers.binance.com/en/docs/catalog/investment-and-services-simple-earn/api/rest-api/flexible-locked).

실계좌 검증에서는 기존 거래 기록과 잔여 원금이 있어 `history_zero`, `residual_assets_zero`는 false다. 이는 이번 작업에서 보존한 정상 데이터이며 시작 준비 실패를 뜻하지 않는다. 실계좌 검증은 백엔드의 주문 비활성 실행으로 수행했으며, 데스크톱 화면에서 실거래를 시작하지 않았다.

전체 테스트 출력의 Phase 13 GAP 문구는 배포 준비도 검사 fixture의 예상 출력이다. 이번 결과는 로컬 장애 수정 검증이며, 별도의 배포·공증·전체 의존성 감사 완료를 의미하지 않는다.
