# Earn 보상 잔고 대조와 종료 차단 수정

검증일: 2026-09-16 (KST)

종료 시 계좌 연결을 닫은 뒤에도 보상 검증이 연결 준비 상태를 요구해 정상적인 Earn 보상까지 잔고 불일치로 판단하던 문제를 수정했다. 시작·재연결·종료가 같은 대조 함수를 사용하며, 종료 담당 작업은 거래 연결이 닫힌 상태에서 반복 REST 조회로 검증한다. 신규 거래 차단, 소유권·체결·미완료 주문·장부 검증은 유지한다.

## 실제 계좌에서 확인한 결과

| 항목 | ETH 수량 |
| --- | ---: |
| 열린 포지션 | 0 |
| 잔여 원금 | 0.00009600 |
| 확인된 Earn 보상 | 0.00000001 |
| Earn 보관량 | 0 |
| 예상 현물 잔고 | 0.00009601 |
| 거래소 현물 잔고 | 0.00009601 |
| 미해결 차이 | 0.00000000 |

검증 공식은 `포지션 + 잔여 원금 + 확인된 보상 - Earn 보관량 = 현물 잔고`다. 보상은 전략 포지션·매매 손익·잔여 원가에 합산하지 않는다. 기존 Binance 읽기 전용 Earn 조회를 사용하며, 상환 보상의 근거는 [공식 Get Flexible Rewards History API](https://developers.binance.com/en/docs/catalog/investment-and-services-simple-earn/api/rest-api/flexible-locked#get-flexible-rewards-history)의 REALTIME 보상이다.

초기 실계좌 검사는 허용 IP 문제로 401/-2015 응답을 받았다. 사용자가 현재 IP를 추가한 뒤 재검사에 성공했다. 주문을 비활성화한 별도 검증 runtime과 기록 복사본에서 시작 대조, 종료 준비, 종료 승인, CLOSED 상태를 확인했다. 고아 프로세스 정리 전후 모두 같은 수량과 기록 해시를 확인했다.

## 구현

- 불변 대조 결과를 계좌 버전, 포지션 수량·원가·소유자, 거래 이력 해시, 잔여 이관, 소유권 상태에 연결한다. 자료가 달라지면 이전 결과를 재사용하지 않는다.
- 보상 근거와 현물 잔고를 각각 반복 조회한다. 동일 종료 작업의 후속 검사에서는 같은 검증 결과를 사용해 원금만 다시 비교하던 충돌을 없앴다.
- 연결 조건 예외는 종료 작업 소유 스레드에만 허용한다. 조회 뒤마다 종료 기한과 소유권을 확인하며 늦은 응답은 종료를 승인할 수 없다.
- 조회 불가, 조회 중 변경, 실제 수량 불일치, 잘못된 Earn 근거를 구분한다. 일시 오류와 조회 중 변경은 기존 120초 종료 제한 안에서 재시도한다.
- 계좌 snapshot과 `/v1/shutdown/prepare`에 원금·보상·보관량·현물 잔고·차이·확인 시각을 제공한다. Python 계약, 생성 TypeScript 계약, 화면 검증기를 함께 갱신했다. 수량은 소수 문자열로 유지한다.
- 보유 자산의 `ETH · 대조 내역`에서 상세 내용을 열 수 있다. 종료 중 진행 상태와 차단 오류에도 대조 결과를 표시한다. 기존 단일 종료 작업과 중복 요청 병합 경로를 유지한다.

실계좌의 열린 포지션·미체결 주문·주문 목록·미완료 기록이 없음을 확인한 뒤, 기존 ORPHANED 백엔드 PID 2906의 경로·시작 시각·부모 PID·소유권 식별자를 재확인하고 SIGTERM으로 정리했다. 래퍼 PID 2904도 종료됐다. 이는 기존 결함 버전에 대한 운영 복구다. 거래소를 다시 읽기 전용으로 대조한 뒤 OS 잠금을 독점 획득해 기존 소유권만 RELEASED로 갱신했다.
