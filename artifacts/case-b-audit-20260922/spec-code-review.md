## 2. 지표 산출

- `application/market_evaluation_builder.py:775–788`: 마감 %B는 해당 봉 포함 마지막 20개 확정 종가로 별도 계산.
- 같은 파일 `841–845,869–870`: 신호봉의 low와 직전 3개 확정봉의 low를 분리하며 현재 봉은 이전 3봉에 포함하지 않음.
- `domain/trading/conditions.py:75–77`: 직전 3봉 low의 최솟값을 사용.
- `application/market_evaluation_builder.py:726–737`: 확정봉 slope는 확정 종가열의 EMA를 사용.
- `domain/market/ema_slope.py:8–13,43–50,77–99,129–135`: EMA9 (첫 9개 종가 평균으로 seed, alpha 0.2), 최근 6개 EMA9를 x=0..5로 선형회귀한 기울기 / 현재 종가 ×100, 최종 소수점 8자리.
- `domain/trading/stm.py:523–538`: WAIT_SIGNAL은 확정 30분봉에서만 평가하고 WAIT_PULLBACK은 시장 데이터 갱신마다 재평가.

중요한 명세 한계: 사용자가 지정한 Lower_bb 명세에는 slope의 임계값과 30분봉 기준은 있지만 EMA 기간, 회귀 창, 정규화 공식을 전부 명시하지 않는다. 따라서 위 수학은 구현에서 확인한 정의다. 설계자의 백테스트가 다른 slope 공식을 썼다면 결과가 달라질 수 있다. 단지 마감 %B만 비교해서 신호가 있었다고 확정하면 안 된다.

3. 새 30분봉에서 하단 재접촉: `global_transitions.py:156–181`의 G-03이 기존 이벤트·신호를 지우고 새 접촉 기준으로 시작한다. `stm.py:229–232`에서 전역 조건이 B보다 먼저 실행되므로 기존 WAIT_PULLBACK도 새로 시작할 수 있다. 명세 §5.6 751행은 새 30분봉 재접촉을 기존 이벤트 종료로 명시한다. 다만 §3.4의 3시간 대기, §5.7 764행과 §7.4 1061행의 “Case B 확정 전에” 재접촉 문구는 해석상 확인이 필요한 부분이다. 실제 로그에서 이 때문에 놓친 경우가 확인되기 전에는 버그로 단정하지 않는다.
4. 상단 접촉: 현 코드 `global_transitions.py:44–89,113–123`은 주문·보유가 없으면 기존 하단 이벤트와 B/C 신호를 지우고 하단 감시로 돌아간다. 이전 신호로 이후 눌림을 매수할 수 없다.

REGIME 관련: `domain/trading/logic_registry.py:133–156`은 TYPE_0만 지원한다. `stm.py:47–58,78–86`에 따라 선택한 regime은 세션 중 고정된다. 현재 하단 전략 내부에 실시간 추천 regime이 바뀌었다는 이유만으로 B만 차단하는 별도 조건은 없다.
