# Case B 평가 공백 검토 — 공개 과거 시세 보완 결과

2026-09-22. `audit.sqlite`를 읽기 전용 조회했고, 공개 Binance 30분봉 및1분봉 자료와 대조했다. 18개 실행 프로세스의20개 전략 세션에서 실제 평가, 시세 수신, 일시정지, 종료를 구분했다. 아래 시각은 모두 KST다.

## 결론

**주요 평가 공백에서 추가로 확정할 Case B 매수 누락은 찾지 못했다.** 다만 실제로 거래 판단이 멈춘 시간이 존재했으며, 공백을 정상 운용으로 취급하거나 “로그에 B 신호가 없으므로 기회도 없었다”고 결론내리면 안 된다.

과거 시세 보완 전에는9/15 23:30과9/10 장시간 정지 구간에 자료 부족이 있었으나, 공개 시세로 다음처럼 해소했다.

- **9/10 04:36~13:01:** 04:40에는 적격 하단 터치가 있었고10:00봉에서 회복 신호의 숫자 조건이 충족됐다. 그러나05:00의 새30분봉 하단 재접촉이 기존 후보를 종료하며, 새 터치 BBW는0.02 이상이었다. 따라서10:00에 사용할 유효한 Case B 후보가 남아 있지 않는다. 명세5.6의 새30분봉 하단 재접촉 종료 규칙을 빠뜨리면 잘못된 추가 매수 누락으로 집계하게 된다.
- **9/10 21:00:** 마감 처리 실패가 있었지만, 복구 직후 같은 확정봉 지표에서%B와 slope가 모두 실패했다.
- **9/11 14:54~17:01:** 중단 직전은 하단 터치 대기 상태였고 이후1분봉 최저가까지 넣어 계산해도%B 최저0.78415614였다. 하단 터치가 없어 Case B 후보 자체가 시작되지 않는다.
- **9/15 22:41~23:53 첫 사용자 중지 요청:** 23:00과23:30 두 마감 모두%B와 slope가 실패했다.
- **9/17 03:06 이후:** 상단 밴드 안전 종료로 세션 자체가 끝났다. 이후 시세 수신을 정상 전략 운용 시간으로 세지 않는다.
- **9/20 06:22 이후:** Case C 실제 보유 및 B 진입 일시정지 상태였다. 동시 Case B 매수를 해야 했다고 볼 수 없다. 정상적인 C 자동청산까지 가정한 이후 경로는 실제 기록과 다른 가상 시나리오다.

## 자료 검증

- `public-candles-full.json` 및 `public-candles-sep15.json`의 Binance 공개30분봉은 DB의295개 원본 확정봉과 **시가·고가·저가·종가·거래량 모두 일치**, 차이0개다.
- BB는 확정봉20개 종가, 모분산,2σ로 독립 계산했다. 실시간 계산은 해당 진행봉 이전19개 확정종가+당시 실제30분봉 업데이트의close다.
- EMA9는 최대500개 종가를 사용해 첫9개 평균seed, α=.2, 최근6값OLS, 종가정규화×100,8자리 HALF_EVEN으로 계산했다. 9/10 초반은 공개자료 시작점 때문에500개에 못 미치는 약470개 입력이 있다. 충분한 워밍업 후 계산이며, 최초 앱seed 비공개에 따른 형식적 한계는 유지한다. 임계값에 영향을 줄 규모의 경계 사례는 여기 없다.
- `public-1m-sep10-gap.json`(506봉), `public-1m-sep11-gap.json`(128봉)은 진행중30분봉의 가능한 최저가에 따른 하단 접촉/Case C flush 발생 가능성을 추가 점검하는 데 사용했다. 1분봉 저가로 만든 수치는 **실제 앱이 수신한 current-price update와 구분**했다.
