# UI 전체 코딩 컨벤션 재점검 결과

점검일: 2026-09-17

이전에 수정한 파일로 범위를 제한하지 않고 `git ls-files UI`의 전체 374개 파일을 점검했다. 이번 재점검에서 296개 파일의 주석과 공백을 보완했다. 이전 요청에서 이미 수정되어 있던 파일은 그대로 보존했으며, Git 기준 누적 변경 파일은 298개다. 변경 전 비교 기준은 이번 요청을 시작할 때 저장한 작업 폴더이므로 이전 작업의 미커밋 변경도 포함한다.

## 적용 내용

`CODING_CONVENTIONS.md`의 실제 구분은 §4 빈 줄과 §5 주석이다. Python 문법 전용 규칙은 그대로 삽입할 수 없으므로 TypeScript/JavaScript의 JSDoc·`//`, CSS의 `/* */`, Rust의 `///`·`//`, 설정 파일의 `#`로 같은 설명 원칙을 적용했다.

- 최상위 함수·클래스 사이 두 빈 줄, 클래스 메서드 사이 한 빈 줄, 작업 단위 사이 빈 줄을 정리했다.
- 여러 문장이 수행하는 작업 바로 위에 블록 주석을 보완했다. 테스트에서는 준비·입력·결과 확인·정리 단계를 구분하고, 상태 머신과 Controller에서는 판단·요청·실행·결과 반영 경계를 설명했다.
- 한 문장을 설명하는 주석은 코드 뒤에 두 칸 이상 띄워 추가했다.
- 클래스·함수 설명의 기능, 인자, 반환값, 작성 날짜를 점검했다. 명명된 선언 점검 대상 676개와 Rust 함수 271개에서 필수 설명 항목 누락은 발견되지 않았다. 이 수치는 모든 익명 콜백을 독립 함수 문서로 집계한 값은 아니다.
- 재수출·타입·단순 설정 등 내부 작업별 설명이 적합하지 않은 소스에는 파일 역할을 설명하는 한 줄 주석을 맨 위에 보완했다.
- 이름, 외부 계약, 상태 전이, API 인자, 화면 문구, 테스트 조건·기대값은 변경하지 않았다.

대표적으로 [App.module.css](../../UI/src/app/App.module.css)는 레이아웃·로딩·종료·연결 복구 영역의 역할을 설명하고, [App.test.tsx](../../UI/src/app/App.test.tsx)는 hover 진단과 REGIME 선택·시작·필터·CSV·중지 흐름의 작업별 주석과 문장 주석을 보완했다. [UISTM.ts](../../UI/src/app/machines/UISTM.ts)와 Controller뿐 아니라 나머지 기능, 어댑터, 테스트, 스타일, 실행 스크립트, 네이티브 소스도 점검했다.

JSON은 주석을 허용하지 않으며, 잠금 파일과 자동 생성 계약 코드는 도구가 관리한다. 이 파일들과 시각 자산은 원본을 유지했다. 기존 설명 문서도 코드 주석 추가 대상에서 제외했다. 이미 필요한 설명이 있는 파일에는 중복 설명을 추가하지 않았다. 전체 파일별 판단과 변경 전후 SHA-256은 [file-audit.json](file-audit.json)에 기록했다. 의존성 폴더, 컴파일 결과, 캐시 등 생성 파일은 소스 점검 대상에 포함하지 않았다.

## 동작 동일성 확인

| 검사 | 결과 |
| --- | --- |
| 변경 전 전체 UI 테스트 | 60개 파일, 660개 통과 |
| 변경 후 전체 UI 테스트 | 60개 파일, 660개 통과 |
| 네이티브 라이브러리 테스트 | 59개 통과 |
| TypeScript 타입 검사 | 통과 |
| Production build | 통과 |
| `git diff --check` | 통과 |
| TypeScript/JavaScript 구문 트리 비교 | 237개 파일에서 주석·위치 정보 외 차이 없음 |
| CSS 구문 트리 비교 | 37개 파일의 선택자·속성·값·우선순위·순서 동일 |
| Rust 토큰 비교 | 23개 파일의 문서 주석 제외 토큰 동일 |
| HTML 비교 | 2개 진입점의 주석 제외 DOM·텍스트 동일 |
| 설정 비교 | Cargo.toml 해석값과 YAML·gitignore의 유효 내용 동일 |
| JSON·잠금 파일·시각 자산·생성 계약 | 변경 전후 바이트 동일 |

구문 트리 비교는 테스트 파일도 포함한다. 테스트 삭제나 기대값 완화 없이 기존 입력과 기대 결과를 유지했다. UI 테스트에는 로컬 backend fixture를 사용하는 연동 검증이 포함된다.

변경 전 소스로 production build를 재현한 결과, 저장해 둔 변경 전 산출물 612개의 해시와 모두 일치했다. 변경 후 산출물도 612개이며, 601개는 바이트 단위로 동일하다. 나머지 11개는 CSS 주석·줄 번호 변화가 CSS Modules의 자동 생성 클래스명과 이를 포함하는 산출물 파일명에 반영된 차이다. 333개 클래스명을 일대일로 대응시키고 산출물 파일 참조 이름을 대응시킨 뒤 비교하면 11개 파일도 내용이 완전히 동일하다. CSS 선언 값이나 실행 코드의 추가 차이는 없다.

## 검증 범위의 한계

이번 작업에서 실제 Binance 주문, GUI를 통한 데스크톱 수동 조작, 장시간 background soak, Windows 환경 실행은 수행하지 않았다. 대신 모든 대상 소스의 실행 구조·CSS·설정이 동일한지 비교하고 기존 자동 테스트와 production build를 검증했다. 현재 자동 검증 범위에서는 동작 차이가 발견되지 않았다.
