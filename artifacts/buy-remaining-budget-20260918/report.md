# 잔여 예산 매수 및 구동 문제 수정 결과

작성일: 2026-09-18

총 보유 한도 **10 USDT**를 유지하면서 전략 포지션, 잔여 ETH, 미체결 BUY 예약을 먼저 차감해 주문을 만들도록 수정했다. 전략 진입 조건과 신호 유효기간은 변경하지 않았다. 검증은 모의 거래와 사건 재현으로 수행했으며 실제 매수나 기존 거래·잔여 장부의 데이터 수정은 수행하지 않았다.

## 사건 재현 결과

당시 가격 2,446.43 USDT, 잔여 ETH 0.000096, 수량 단위 0.0001을 적용했다. 모의 거래소의 최소 주문 금액은 5 USDT로 설정해 실제로 제출 가능한 조건을 검증했다.

| 항목 | 기존 후보 | 수정 후 후보 |
| --- | ---: | ---: |
| 주문 수량 | 0.004 ETH | 0.0039 ETH |
| 주문 평가액 | 9.785720 USDT | 9.541077 USDT |
| 잔여 ETH 평가액 | 0.23485728 USDT | 0.23485728 USDT |
| 합산 예상 보유액 | 10.02057728 USDT | 9.77593428 USDT |
| 결과 | 총 한도 초과로 차단 | 한 번 제출·체결, 거래 내역 한 건 반영 |

체결 후 시세 입력 31회를 추가해도 새 주문이 제출되지 않았다. 최소 주문 금액이 10 USDT인 별도 환경에서는 같은 후보 31회에 대해 준비를 한 번만 수행하고 전송 횟수·미체결 주문을 늘리지 않았다.

## 적용한 변경

- 매수 수량 제한과 최종 위험 검사가 공통 보유액·예약액 계산을 사용한다. 수량 지정과 부분체결 재시도에도 남은 예산과 단건 상한을 적용하며 거래소 단위로 내림한 뒤 다시 검사한다.
- 예산 0, 수량 내림 결과 0, 거래소 최소 조건 미달을 `RISK_BUY_BUDGET_INSUFFICIENT` 보류로 처리한다. Case B·C는 정상 신호 감시로 돌아간다. 정책 불일치·긴급정지·잘못된 필터의 차단은 유지한다.
- 보류 중 로컬 재평가는 계속한다. 동일 조건의 원격 준비는 30초 간격으로 제한하며 잔고·예약·정책·신호 또는 최소 주문 충족 가능성이 바뀌면 즉시 다시 준비한다. 실제 제출은 항상 최신 거래소 필터를 검사한다.
- 보류의 시작·변경·해소와 억제 횟수를 기록한다. 신호 만료, STOP, 세션 종료 시 대기 상태를 정리한다.
- 전송 전 폐기한 준비 자료를 정리한다. 전송됐거나 결과가 불명확한 주문의 준비·전송 증거는 보존한다.
- 화면의 마지막 판정을 ‘최근 매수 판정’으로 표시하고 현재 운영 경고와 분리했다. 전략 포지션·잔여 ETH·합산 보유액, 판정 시각, 당시 한도·남은 예산·조정 전후 금액을 표시한다. 이전 데이터의 누락 값은 ‘확인 불가’로 표시한다.
- Python 직렬화, 생성 TypeScript 계약, 입력 검증, 데스크톱 진단 허용 목록을 함께 갱신했다.
- 시세 입력 중단은 `market_input_stalled`, 입력이 있어도 전략 평가가 멈춘 경우는 `market_evaluation_stalled`로 기록한다. 실제 마지막 관측 시각·경과 시간과 60초 감지 기준 시간을 구분했다. 기존 감지 시간과 자동 복구 동작은 유지한다.
- UI 연결 종료 2회와 재연결을 모의한 테스트에서 전략 상태를 유지하고 주문 한 건만 처리했다.
